# KB object model: changed requirements

Changed on 2026-11-20, after the design review by Frieren and the user's two points.

- **R1.** Was: a page in no collection of its domain is listed by the check, as a break. Now: it is untyped, listed, and not a break. Why: the user said some pages have frontmatter and some do not.
- **R2.** Was: the kind "a link to another object". Now: `link:<type>`. Why: the check could not find the object a link names with no type.
- **R5.** Was: a whole never copies a part's fields, and part values had no kind. Now: the type declares the kind of each part value. Why: grams had no place in the table. The copy rule needs a reading of the content, which no script does.
- **R9.** Was: `kb-check.py` reads each table, and the breaks left out the area. Now: a new script of the `kb` skill, next to `kb-check.py`, and the area is a break. Why: `kb-check.py` is built by the parent level, and a path is built by one level only.
- **R12.** Was: the check fails on the food domain as it is. Now: it lists the food pages as untyped, then checks them after the move. Why: an untyped page is not a break.
- **R13.** New: a type can extend another, as in OOP. Why: the user asked for an OOP graph.
- **Grill of R14, R15 and R16, 2026-11-20.** Fern settled three points. The picture reads each KB root less the deprecated `finance` and `travel` repos. It is one HTML page, since a graph block has no buttons. The focus counts five levels: all KBs, KB, domain, folder or type, and field.
