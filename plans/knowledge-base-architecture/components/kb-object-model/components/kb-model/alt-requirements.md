# KB model: changed requirements

- **R7. A first model from the pages:** For a KB with no model, the script writes a first model from the frontmatter of its pages. The script writes it into the KB, and Claude commits it on the `main` of that KB. After that, the user edits the model, and the script never writes it again. Merged 2026-11-20 into R11.
- **R8. Food first:** The food domain of `personal` gets its model first. The check passes on it, or names each file and rule that breaks. Merged 2026-11-20 into R11.
- **R1. One model for each KB:** Each KB has one Quint model, `kb-model.qnt`, next to its root `CLAUDE.md`. It holds every type of every domain of that KB. Each type has its areas, its `is_a` parent, its fields, the types it is made of, part of or links to, and the types its pages may cite. A citation is a link in the body of a page. *(the user, 2026-11-20)* Changed 2026-11-20 into R13, after the requirements review.
- **R2. Shape as data, rules as functions:** The model holds each type as a value, so a type can carry its parent, its marks and its links. The rules are pure functions in one shared rules file of the `kb` skill, which each KB model imports. A link between objects is a path, and a rule checks the type of the file at that path. Changed 2026-11-20 into R12, after the requirements review.
- **R3. A field has a kind and marks:** Each field has a name, a kind, a required mark and a public mark. A type gets each field of each type over it by `is_a`. Changed 2026-11-20 into R12, after the requirements review.
- **R6. The drift check:** A script of the `kb` skill reads the files of a KB, writes them as Quint data, and runs the model on them. It prints one line per break, with the path, the rule and what the rule is about, and exits 1. With no break, it lists the untyped files and exits 0. If the model does not typecheck, the script exits 2. - Design input: The breaks of a file are a wrong area, an extra or missing field, a wrong kind, a `type:` that the model does not define, a wrong part, link or citation, and a link to no file. The breaks of the model are a parent, part or citation type that it does not define, and an `is_a` cycle. Changed 2026-11-20 into R14, after the requirements review.
- **R9. Links and inheritance first:** The references, the inheritance and the links between objects matter most. Their rules are built and tested first. The check of the public mark waits, as R4 says. *(the user, 2026-11-20)* Changed 2026-11-20 into R15, after the requirements review.
- **R10. No object without a reference:** Each staging and consolidated object links to at least one other object, by a citation, a part or a link. An object with none is a break of the drift check. *(the user, 2026-11-20)* Changed 2026-11-20 into R16, after the requirements review.
- **R11. A first model, food first:** For a KB with no model, the script writes a first model from the frontmatter of its pages. The script writes it into the KB, and Claude commits it on the `main` of that KB. After that, the user edits the model, and the script never writes it again. The food domain of `personal` gets its model first. The check passes on it, or names each file and rule that breaks. Changed 2026-11-20 into R17, after the requirements review.
- **R12. Types as data, rules as functions:** The model holds each type as a value, so a type can carry its parent, its fields and its links. Each field has a name, a kind, a required mark and a public mark. The kinds are those of R39 of the parent. A type gets each field of each type over it by `is_a`. The rules are pure functions in one shared rules file of the `kb` skill, which each KB model imports. A link between objects is a path, and a rule checks the type of the file at that path. Changed 2026-11-20 into R19: a skill folder holds no Quint file, so the rules file sits in `.claude/lib/kb-model/`.
- **R14. The drift check:** A script of the `kb` skill reads the files of a KB, writes them as Quint data, and runs the model on them. It prints one line per break, with the path, the rule and what the rule is about, and exits 1. With no break, it lists the untyped files and exits 0. If the model does not typecheck, the script exits 2. - Design input: The fields of a page are its frontmatter keys and its `- Key: value` lines before the first `##`. The keys `type:`, `part_of:`, `made_of:` and `links_to:` are no fields. The breaks of a file are a wrong area, an extra or missing field, a wrong kind, a `type:` that the model does not define, a wrong part, part value, link or citation, a link to no file, and a whole that is part of itself. The breaks of the model are a parent, part or citation type that it does not define, and an `is_a` cycle. A citation is a relative Markdown link in the body to a file of the KB. The `is_a` chain and the part chain are followed as deep as the count of types and of files, so no limit cuts a real chain. Changed 2026-11-20 into R20: `is_a:` is no field too, and the `kb` skill names the script.
- **R20. The drift check:** A script of the `kb` skill reads the files of a KB, writes them as Quint data, and runs the model on them. It prints one line per break, with the path, the rule and what the rule is about, and exits 1. With no break, it lists the untyped files and exits 0. If the model does not typecheck, the script exits 2. The `kb` skill names the script and its commands. - Design input: The fields of a page are its frontmatter keys and its `- Key: value` lines before the first `##`. The keys `type:`, `is_a:`, `part_of:`, `made_of:` and `links_to:` are no fields. The breaks of a file are a wrong area, an extra or missing field, a wrong kind, a `type:` that the model does not define, a wrong part, part value, link or citation, a link to no file, and a whole that is part of itself. The breaks of the model are a parent, part or citation type that it does not define, and an `is_a` cycle. A citation is a relative Markdown link in the body to a file of the KB. The `is_a` chain and the part chain are followed as deep as the count of types and of files, so no limit cuts a real chain. Changed 2026-11-20 into R21: the script sits in `.claude/lib/kb-model/` with the rules file, since the parent level builds the lines of the `kb` skill.
